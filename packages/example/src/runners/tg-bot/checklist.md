# Пример Telegram-бота — чек-лист ручной проверки

**Назначение:** пошаговая проверка примера [Telegram-бота](./README.md) на тестовом боте: подготовка, группы пунктов, колонка «Итог».

---

## Чек-лист ручной проверки

Каждому пункту в колонке «Итог» ставится «пройден» или «не пройден: что видно». Расхождение с живым Telegram — находка: допущение подтверждено — записать в D-UI-67; не подтверждено — правка кода пакета с тестом до выпуска. В колонке «Откуда» — решения пакета ([`docs/decisions.md`](../../../../../docs/decisions.md)) и правила.

### 0. Подготовка

| Действие | Ожидаемое | Откуда | Итог |
|---|---|---|---|
| Взять отдельного тестового бота, не боевого (`Bot.start` снимает вебхук); токен — в `.env` как `EXAMPLE_TG_TOKEN`; id своего аккаунта (и второго, если есть) — в `EXAMPLE_TG_USERS` | Токена нет в `git status`, `git diff`, консоли | D-UI-68 | пройден |
| Остановить любого исполнителя на этом токене (старый бот, `pm2`, второй терминал) | Один токен — один исполнитель: `getUpdates` и вебхук не уживаются, второй получает 409 | D-UI-68 | пройден |
| `bun install`, `bun run example:tg` | В консоли: имя бота, «готов», uuid пользователя B, число команд меню (3); ни токена, ни id людей | D-UI-62, D-UI-64 | пройден |

### А. Запуск и Telegram

| Действие | Ожидаемое | Откуда | Итог |
|---|---|---|---|
| А1. Открыть бота, нажать кнопку меню слева от поля ввода | Список: «Мои задачи», «Начать работу», «Назначенные мне» (`setMyCommands`, область — личные чаты); в группе меню нет | D-UI-64 | пройден |
| А2. Открыть `t.me/<бот>?start=hello` | Открывается вход приложения, как `/start` | D-UI-64 | пройден |
| А3. Заблокировать бота и разблокировать | Пример не падает, в консоли тишина (апдейт `my_chat_member` приходит, но вне группы в журнал не пишется); после разблокировки `/start` работает | D-UI-62, D-UI-65 | пройден |
| А4. Запустить второй экземпляр на том же токене | Второй завершается с понятным сообщением о конфликте `getUpdates`, токена в тексте нет; первый продолжает | D-UI-68 | пройден |

### Б. Диалог (учебная сторис, пользователь A)

| Действие | Ожидаемое | Откуда | Итог |
|---|---|---|---|
| Б1. `/start` | «Мои задачи», «Задач пока нет. Напишите название — создам задачу.», кнопки «Создать задачу», «К части», «Закрыть»; ниже серые с «🚫»: «Открыть задачу», «Выполнить выбранные», «Дальше», «Предыдущая страница», «Отметить задачу» | D-UI-62, D-UI-105 | |
| Б2. Написать «Хлеб», затем «Молоко» | После каждого — «Задача создана» и список с этими задачами (открытых задач не больше трёх: четвёртая получает «Открытых задач слишком много — сначала выполните часть.») | D-UI-62 | пройден |
| Б3. С тремя открытыми задачами (две на странице) нажать «Дальше», затем «Предыдущая страница» | То же сообщение правится на месте, новых нет; кнопки «Назад» при листании не появляется | D-UI-61, D-UI-108 | |
| Б4. С тремя открытыми задачами быстро дважды нажать «Дальше» (сверить на ходу) | Либо подсказка «Эта кнопка устарела.», либо ответ без подсказки; сообщение не ломается, лишних сообщений нет | D-UI-62 | пройден: второе нажатие — как одно, без подсказки |
| Б5. Нажать любую кнопку | «Часики» на кнопке исчезают не дольше секунды: ответ на каждое нажатие | D-UI-61 | пройден |
| Б6. «Отметить задачу», выбрать задачу, «Выполнить выбранные», «Да» | Задача отмечена `[x]`, затем подтверждение «Выполнить выбранные задачи?», после «Да» задача выполнена, список обновлён | D-UI-61 | пройден |
| Б7. Вид списка с отмеченной задачей и карточки открытой задачи | «Выполнить выбранные» и «Выполнить» зелёные, остальные кнопки без цвета | D-UI-67 | пройден |
| Б8. «Открыть задачу», выбрать задачу; повторить для названий «🧀 Сыр» и «👨‍👩‍👧 Семья» | Строка «Напоминание (пример): 20 ноября 2026, 12:00» выделена как дата (нажатие показывает дату в **локальном** времени человека); выделение ровно по тексту, не смещено эмодзи (UTF-16) | D-UI-67 | пройден |
| Б9. Название, составленное из служебных знаков Markdown и HTML: слово между звёздочками, подчёркивания, цифра в квадратных скобках, буква в круглых скобках, тег «жирный» в угловых скобках и амперсанд (одной строкой) | Везде показывается как есть, без жирного и ссылок | D-UI-61 | пройден |
| Б10. Название на 200 знаков; название, где эмодзи стоит на 63–64 знаке | В выборе задачи подпись кнопки ≤ 64 знаков UTF-16 (с «…»), пара эмодзи не разорвана, сообщение доставлено, 400 в консоли нет; в консоли `warn` «текст обрезан по лимиту мессенджера» | D-UI-39, D-UI-61 | пройден (`warn` обрезки подписи виден в консоли пробы Е8) |
| Б11. При открытом списке отправить `/assigned` | Сообщение списка остаётся с прежним текстом, кнопок под ним нет, ошибки в консоли нет (правка клавиатуры без разметки) | D-UI-61 | пройден |
| Б12. Бот выключен; нажать 2–3 кнопки; подождать минуту; запустить | Просроченные нажатия: `warn` «Bot API отказал» в консоли без падения; затем новые нажатия работают | D-UI-61 | пройден (`warn` не сверен) |
| Б13. Перезапустить бота; нажать кнопку прежнего сообщения | Нажатие получает ответ (подсказка «Эта кнопка устарела.»; сверить на ходу); новый `/start` даёт новый экран | D-UI-62 | пройден |
| Б14. Сравнить трассу (`EXAMPLE_TG_TRACE`) со снимками превью | `text`, `entities`, `reply_markup` живых запросов совпадают со снимком для того же экрана | D-UI-67 | |

### В. Два человека (нужен второй аккаунт Telegram; нет — отметить «не пройден: нет второго аккаунта»)

| Действие | Ожидаемое | Откуда | Итог |
|---|---|---|---|
| В1. B ни разу не писал боту; A на карточке задачи нажимает «Назначить» и вводит uuid B из консоли | У B ничего нет; в консоли `warn` «сообщение беседы не доставлено» (бот не может начать диалог), у A — без падения | D-UI-61 | частично: тот же отказ 403 проверен на блокировке (В4); второго аккаунта нет |
| В2. B пишет `/start`; A снова назначает | B получает «Вам назначена задача: …» с кнопкой «Назначенные мне» | D-UI-61 | не пройден: нет второго аккаунта |
| В3. A сразу после назначения нажимает «Выполнить» на той же карточке | B получает «Поручение выполнено: …» с кнопкой «Назначенные мне» | D-UI-61 | не пройден: нет второго аккаунта |
| В4. B блокирует бота; A назначает | `warn`, без падения; после разблокировки доставка возобновляется | D-UI-61 | пройден на одном аккаунте пробой: заблокирован — `warn` 403 «bot was blocked by the user», «не доставлено», без падения; разблокирован — доставлено |

### Г. Личность и безопасность

| Действие | Ожидаемое | Откуда | Итог |
|---|---|---|---|
| Г1. Аккаунт не из списка пишет `/start` и жмёт кнопку чужого экрана (кнопка — переслать сообщение) | Тишина на сообщение, ответ без текста на нажатие, в консоли `warn` без id | D-UI-62 | не пройден: нет второго аккаунта |
| Г2. `ss -ltnp \| grep bun` при работающем примере | Ни одного слушающего порта (только исходящий опрос) | D-UI-62 | пройден |
| Г3. Отключить сеть, подержать минуту, включить; вывод консоли — в файл | Опрос восстанавливается; `grep` по токену и по id пользователей в выводе пуст | D-UI-61, ERR-07 | |
| Г4. Добавить бота в группу, написать там `/start` | Бот молчит (диалог только в личном чате, команды меню — только в личных), падения нет | D-UI-62, D-UI-64 | пройден |

### Е. Проба Bot API

Запуск — `bun run example:tg:probe <chat_id>`; пункты идут сообщениями в чат в этом же порядке. Их сообщения показывает настоящий код пакета: сущности, страж лимитов, `retire`.

| Проба | Ожидаемое | Откуда | Итог |
|---|---|---|---|
| Е1. Все стили: жирный, курсив, зачёркнутый, код, блок кода, цитата | Видны, как в превью; 400 нет | D-UI-61 | пройден |
| Е2. Ссылка поверх строчного кода | Видна ссылка, без вида кода: ссылка сильнее кода (код под ссылкой Telegram показывает без ссылки) | D-UI-61 | не пройден до правки: веб и десктоп показывали код без ссылки — теперь код под ссылкой снимается (D-UI-61) |
| Е3. Два блока кода подряд | Не слипаются в один | D-UI-61 | пройден |
| Е4. Код внутри цитаты | Доставлено; код внутри цитаты — обычным текстом | D-UI-61 | пройден |
| Е5. Момент: relative, dateTime, date, time; те же с жирным, цитатой, ссылкой, кодом | Первые четыре — дата или время; с жирным и цитатой — оба; со ссылкой — ссылка, дата снята; с кодом — дата снята; на клиенте без `date_time` — запасной текст | D-UI-67 | пройден: жирный с датой — дата без жирного; десктоп Linux не выделяет дату в цитате, веб выделяет |
| Е6. Эмодзи и составные знаки (семья, флаги) перед сущностью | Выделение ровно по тексту, не смещено | D-UI-61 | пройден |
| Е7. `retire` с выбранным вариантом (по Enter в консоли) | Текст сообщения прежний, под ним строка «Вы выбрали: <подпись>», кнопок нет. Отказ Telegram (400) — `warn` в консоли с описанием из ответа | D-UI-92 | не пройден после D-UI-92 |
| Е8. Подпись кнопки ровно 64 и 65 знаков, кириллица и эмодзи | 64 принята, 65 обрезана стражем с «…»; сообщение доставлено | D-UI-39, D-UI-67 | пройден: 65 обрезана с «…» и `warn`; длинные подписи клиенты ещё и сами обрезают по ширине |
| Е9. 100 и 101 кнопка | 100 принято; 101-я кнопка отброшена стражем (`error` в консоли про лимит кнопок), сообщение доставлено | D-UI-39, D-UI-67 | пройден |
| Е10. Правка с пустой клавиатурой | Текст изменился, кнопки исчезли без ошибки | D-UI-61 | пройден |
| Е11. Пробелы по краям текста при сущности | Сущность не сместилась | D-UI-61 | пройден |
| Е12. Правка тем же содержимым | Без ошибки: «message is not modified» считается успехом | D-UI-61 | пройден |
| Е13. Текст ровно 4096 и 4097 знаков | 4096 доставлен; длиннее — обрезан стражем с «…» и `warn`, доставлено | D-UI-39 | пройден |

### Ж. Отключённое, поля, справка, «Назад»

| Действие | Ожидаемое | Откуда | Итог |
|---|---|---|---|
| Ж1. `/start` в пустом списке, нажать «🚫 Открыть задачу» | Вверху чата короткий тост «Задач нет» (не окно с «OK»; ответ без `show_alert`), «часики» исчезли, сообщение и кнопки прежние, новых сообщений нет. Тост не заметен — записать находку (окно — отдельным срезом) | D-UI-105 | |
| Ж2. Пометка «🚫» в подписи на мобильном, десктопе и в вебе | Подпись читается и не обрезана («🚫 Предыдущая страница») | D-UI-105, D-UI-108 | |
| Ж3. «К части»; затем «Напомнить» в карточке задачи | Подсказка: «Введите: Часть / Номер части списка, с первой / Пример: 2 / Пределы: от 1 до 99, целое»; ввод 0 — отказ с текстом поля, ввод 2 — переход. У «Напомнить»: «Срочно» — подсказка и выбор «Да»/«Нет», «Когда» — подсказка и пример | D-UI-106 | |
| Ж4. `/help` в «Мои задачи» | Отдельное сообщение «Справка: Мои задачи …» с разделами «Что можно сделать» (отключённые — «недоступно: причина») и «Куда можно пойти»; прежнее сообщение со списком не изменилось, его кнопки работают | D-UI-107 | |
| Ж5. Меню команд слева от поля ввода и при вводе «/» | Только «Мои задачи», «Начать работу», «Назначенные мне»; `/help` в списке нет, но команда работает. Клиент ждёт `/help` в меню — записать находку | D-UI-107 | |
| Ж6. Список → «Хлеб» → «Открыть задачу» → «Хлеб» | В карточке последняя кнопка «Назад»: возвращает на предыдущий экран тем же сообщением. На списке без перехода «Назад» нет; «Дальше» и «Предыдущая страница» её не добавляют | D-UI-53, D-UI-108 | |
| Ж7. `/back` | В карточке — то же, что «Назад». На экране без пути прежнее сообщение теряет кнопки, экран показан новым сообщением, ошибки нет | D-UI-53, D-UI-108 | |
| Ж8. Создать «Хлеб» → «Открыть задачу» → «Хлеб» → «Назначить», ввести `00000000-0000-4000-8000-000000000001` (себе; второй аккаунт не нужен) → `/assigned` → «Карточка исполнителя» → «К моим задачам» → «Назад» → «Назад» | «К моим задачам» открывает «Мои задачи» с «Назад» в конце; первое «Назад» — карточка, второе — «Назначенные мне»; на «Назначенные мне» кнопки «Назад» нет | D-UI-108 | |
