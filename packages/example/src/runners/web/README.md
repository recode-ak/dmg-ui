# Пример web-канала

Запускаемый пример подключения `dmg-ui/web-ui` к настоящему браузеру ([D-UI-85](../../../../../docs/decisions.md)): учебное приложение (задачи, поручение другому человеку, уведомление) на странице, сервер на `Bun.serve` с сокетом страничного канала. Он нужен для ручной проверки по чек-листу ниже: поведение в браузере (перетаскивание, окно `<dialog>`, «Назад» и «Вперёд», политика содержимого, пульс сокета, адаптивная раскладка) тестами без браузера не подтвердить.

Как подключить `dmg-ui/web-ui` к своему проекту — в гайде [Web-канал](../../../../../docs/guides/web-channel.md).

Пример не устанавливается и не публикуется: своего `package.json` у него нет, зависимостей он не прибавляет, в `exports` пакета его нет. Запускается из корня репо.

## Запуск

1. `bun install` в корне репо.
2. `bun run example:web`. В консоль идут строка «Готов: http://localhost:4310 и http://127.0.0.1:4310. Люди: Анна, Борис.» и строка «Каталог данных: …». Пропусков людей, заголовков запросов и адресов из браузера в консоли нет.
3. Открыть `http://localhost:4310` в браузере, выбрать человека.

Данные (задачи, пропуска людей) лежат в каталоге данных и переживают перезапуск: так открытые вкладки после остановки и запуска сервера подключаются снова без нового выбора человека. Каталог по умолчанию — `dmg-ui-example-web` во временном каталоге системы, права `0700`; чужой каталог или ссылка на его месте — отказ запуска. Начать с чистого листа — удалить этот каталог (путь печатается при запуске) или задать другой через `EXAMPLE_WEB_DATA`. Каталог данных внутри репо не задавать: данные людей не должны попасть в git.

Остановка — `Ctrl+C` (или `SIGTERM`): сокеты закрываются, сессии освобождаются; команда, которая ждёт в «медленном сервере», не исполняется. Второй сигнал — немедленный выход.

## Оговорки

- **Пример без пароля.** Выбрать человека может любой, кто открыл страницу: сервер выдаёт пропуск тому, чей запрос пришёл с разрешённого источника (`Origin`). Поэтому сервер слушает только `127.0.0.1` и недоступен по сети. Пароля, регистрации и учётных записей в примере нет.
- **Два адреса — `localhost` и `127.0.0.1`.** Оба разрешены как источники и в политике содержимого. Если `localhost` на вашей системе сначала разрешается в `::1` и страница не открывается, используйте `http://127.0.0.1:4310`.
- **Защищённый контекст.** Клиент строит идентификаторы запросов через `crypto.randomUUID()`, который браузер даёт только в защищённом контексте (`localhost`, `127.0.0.1` или HTTPS). Поэтому пример нельзя открыть по адресу локальной сети: ни с телефона по IP компьютера, ни по имени машины.
- **Браузер на другой машине.** Пробросить порт: `ssh -L 4310:127.0.0.1:4310 <машина>`, затем открыть `http://localhost:4310` на своей машине: адрес остаётся `localhost`, защищённый контекст и источник из списка сохраняются.
- **Телефон.** Android: `adb reverse tcp:4310 tcp:4310`, затем `http://localhost:4310` на телефоне; либо режим телефона в инструментах разработчика браузера. iOS без HTTPS проверить нечем. Перетаскивание работает мышью; пальцем — кнопками «Открыть» и «Выполнить», они делают то же самое.
- **Смена человека действует на весь адрес.** Кнопка «Войти как …» меняет cookie пропуска для всех вкладок этого адреса; остальные вкладки остаются прежним человеком до обрыва связи — их нужно обновить. Cookie одна на хост (порт её не разделяет), поэтому две вкладки одного адреса — один человек. Второй человек — второй адрес (`127.0.0.1` рядом с `localhost`) или приватное окно.
- **Cookie не делится по портам.** Браузер шлёт cookie пропуска всем приложениям на `localhost` (и на `127.0.0.1`), поэтому они получают пропуск примера в заголовке; а любой локальный процесс может войти за любого человека: пароля нет.
- **Каталог данных** не задавать там, где писать могут другие пользователи: в нём лежат пропуска.
- **Предел частоты рукопожатий** сервер не ограничивает: у примера нет прокси, а слушает он только петлю.

## Переменные окружения

Читает только `server/main.ts`; остальной код получает значения параметрами. Файл [`.env.example`](.env.example) — те же имена без значений (секретов в примере нет: пропуска людей не в окружении, а в каталоге данных); Bun читает `.env` сам.

| Переменная | Что это | По умолчанию |
|---|---|---|
| `EXAMPLE_WEB_PORT` | порт сервера, 1–65535 | `4310` |
| `EXAMPLE_WEB_DELAY_MS` | «медленный сервер»: сколько мс ждёт команда до исполнения, 0–60000 (см. ниже) | `0` — задержки нет |
| `EXAMPLE_WEB_DATA` | каталог данных: задачи и пропуска людей | `dmg-ui-example-web` во временном каталоге системы |
| `EXAMPLE_WEB_LOG` | уровень журнала в консоли: `debug`, `info`, `warn`, `error` | `info` |

Отказ окружения печатает имя переменной без её значения.

## Люди

| Ключ | Имя | `uuid` учебного пользователя |
|---|---|---|
| `anna` | Анна | `00000000-0000-4000-8000-000000000001` |
| `boris` | Борис | `00000000-0000-4000-8000-000000000002` |

Те же учебные пользователи A и B, что у примера [Telegram-бота](../tg-bot/README.md). «Назначить» в карточке задачи выбирает человека из списка.

## «Медленный сервер»

С `EXAMPLE_WEB_DELAY_MS=6000 bun run example:web` вызов команды (создать, назначить, выполнить) ждёт 6 секунд до исполнения. Задерживается один вызов за раз: пока он ждёт, остальные идут сразу — так вторая вкладка того же человека успевает выполнить то же действие, и в первой видно, как показ «выполнена» до ответа откатывается по отказу (пункт Д3). Остановка сервера во время ожидания — обрыв: задержанная команда не исполняется (пункт Д4).

## Раскладка каталога

Раннер `web` учебного проекта: `client/` — DOM-клиент, `server/` — сервер страниц, `common/` — общие константы, `view/` — модели и жесты оболочки, завязанные на экраны примера, в корне — оболочка (`example-pages.ui-app`, маршруты, раскладки, сборка видов). Модульные виды — `frontend/<m>/web/`; общие виды и помощники без хозяина (идентификаторы разметки, клавиша поля, щелчок ссылки, справка, формы) — `frontend/web-kit/` (D-UI-120, D-UI-121). У каждого каталога свои разрешённые импорты (проверяет `checks/core-import-scanner.ts`):

- `common/` — люди и служебные пути: ничего не знает о соседях;
- `view/` — чистые модели оболочки, завязанные на экраны примера (что видит человек, жесты, черновики полей, перетаскивание): ни DOM, ни `node:`; их делят сервер, клиент и тесты, сами они не видят клиент, сервер и `testing/`;
- `client/` — привязка к браузеру: построение DOM, события, `main.ts`; едет в сборку для браузера (`Bun.build`), типы браузера есть только в его программе `tsc` (`tsconfig.json` рядом с README); не видит сервер и `testing/`;
- `testing/` — общая фикстура тестов (мир примера в памяти): видит `common/`, `view/`, `server/`, но не клиента;
- `server/` — окружение, пропуска, сборка приложения, привязка `Bun.serve`, сборка клиента, «медленный сервер», страница, граф; `main.ts` — единственный читатель окружения и сигналов.

Строки людей (названия задач, замечания, заметки, тексты уведомлений) попадают в DOM только текстом; приёмников разметки в коде нет (проверяет `checks/dom-sink-scanner.ts`), политика содержимого страницы закрывает всё, кроме своих скриптов, стилей и сокета.

## Чек-лист ручной проверки в браузере

Каждому пункту в колонке «Итог» ставится «пройден» или «не пройден: что видно». Находка — правка примера или пакета до тега. Порт по умолчанию — `4310`; если задан другой, замените в адресах.

Идти сверху вниз, начиная с чистого каталога данных: пункты опираются на то, что сделано в предыдущих (задачи, открытые вкладки). Правила учебного приложения, чтобы не споткнуться:

- открытых задач у человека не больше трёх; четвёртая создаётся с отказом «Слишком много открытых задач»;
- в списке по две задачи на странице; под списком кнопки «Дальше» и «Предыдущая страница» (в таблицах «Назад» — всегда «Назад» браузера);
- список идёт в порядке записи: выполненная или назначенная задача уходит в конец списка, часто на следующую страницу; задачи не видно — нажмите «Дальше»;
- назначить можно только открытую задачу;
- в панели карточки исполнителя есть «К моим задачам»: список открывается в основной области, панель остаётся ([D-UI-108](../../../../../docs/decisions.md));
- недоступное действие не пропадает, а серо стоит на месте как обычная отключённая кнопка; причину показывает подсказка при наведении (скринридер читает её описанием кнопки); кнопка достаётся клавишей Tab; Enter и пробел на нём ничего не делают. Пропадает только то, чего вам нельзя вовсе (чужое поручение);
- в «Назначенные мне» «Выполнить выбранные» исполняется, только если задачи назначены вам самим; чужие поручения — действие пропадает после галочки;
- поле создания называется «Название задачи», в нём заранее стоит «Новая задача»: перед вводом стереть. Курсор встаёт в это поле при открытии «Мои задачи» и после каждой созданной задачи; клавиша «/» (вне поля ввода; в русской раскладке — та же клавиша, «.») переводит к нему.

### И. Справка (внешний вид)

Браузерные сценарии (`bun run browser`) проверяют кнопку, дерево доступности, клавиатуру, фокус и состав блока; здесь — только то, что видит глаз. Нужна Анна, «Мои задачи».

| № | Шаг | Что должно быть видно | Итог |
|---|---|---|---|
| И1 | «Мои задачи»: у заголовка области кнопка «Справка» (справа, рядом с названием); нажать её; переключить схему системы на светлую и тёмную; клавишей Tab дойти до кнопки; сузить окно до 360 px | Блок справки открывается под заголовком: название экрана и его подсказка, затем «Что можно сделать» и «Куда можно пойти» списками; читается в обеих схемах (не слит с фоном области, не приглушён как подсказка поля); вокруг кнопки при Tab видно кольцо фокуса; длинные строки на узком экране переносятся, блок не выходит за рамку области и не даёт горизонтальной прокрутки | |
| И2 | Открыть `http://localhost:4310/menu`, нажать «Справка»; затем перейти в «Мои задачи» по ссылке и открыть справку там | В «Начать работу» в списке переходов у «Назначенные мне» через тире подсказка («Смотрите, что вам поручили, и выполняйте поручения»), у «Мои задачи» подсказки нет. В «Мои задачи» «Выполнить выбранные» названо недоступным с причиной «Отметьте открытые задачи» (после галочки у задачи пометки «недоступно» нет); при переходе на другой экран справка закрывается, повторное нажатие «Справка» закрывает блок | |

## Что пример не проверяет

- iOS и работу по HTTPS: без сертификата защищённый контекст есть только у `localhost` и `127.0.0.1`;
- пароль, регистрацию, живую смену человека в открытой сессии: «Войти как …» перезагружает страницу и открывает новое соединение;
- несколько раннеров и запуск за прокси (предел частоты рукопожатий, `Secure` у cookie);
- push-уведомления и работу без сети: уведомления идут только в открытые вкладки, а без связи страница показывает «Нет связи — переподключаемся» и ждёт;
- ускорение попытки переподключения по событиям `online` и `visibilitychange`: у переподключателя пакета нет вызова «попробовать сейчас», пауза между попытками доходит до 30 секунд;
- отмену ожидающего подтверждения: у клиента пакета нет такого вызова, есть только «Подтвердить»;
- перетаскивание пальцем: на телефоне оно не обещается, жесты есть и кнопками.
