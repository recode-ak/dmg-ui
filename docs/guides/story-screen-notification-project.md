## 10. Добавить вид в учебный проект

Памятка для учебного проекта `packages/example/src` ([D-UI-121](../decisions.md)): куда положить экран, сторис или уведомление и где их зарегистрировать. Заготовки файлов проекта-потребителя — командой `dmg-core gen <вид>` (`ui-module`, `story`, `screen`, `notification`; [гайд видов](./gen-kinds.md)): она создаёт файлы и дописывает реестры по маркерам, ниже — что и где, если делать руками или проверять результат. Обозначения: `UI` — `platform/ui/`, `FE` — `frontend/`, `R` — `runners/`; `<m>` — имя UI-модуля, `<story>` — папка сторис. Образец сторис и экрана — модуль `profile` (раздел из одной сторис с переходом во вспомогательный модуль `users`); уведомление (`.ncode`), перекрытие Telegram и общий экран в `shared/` — модуль `todo`.

1. **Описание.**
   - Файл — в `UI/<m>/<story>/`; экран двух сторис — в `UI/<m>/shared/`.
   - Запись — в `UI/<m>/<m>.ui-module.ts`; новый модуль — ещё в `UI/example-ui.set.ts`.
   - Имена Def — в `UI/index.ts` и во вход `packages/example/index.ts`, если их берут тесты других пакетов; состав входа `packages/example/index.ts` закреплён `checks/package-manifest.example.test.ts`.
2. **Достижимость (UI-07).**
   - Экран открывается действием-переходом (`to`) с экрана сторис приложения, сторис — связью `leads` (UI-24), а не новым входом приложения.
   - Вход приложения — только для адреса снаружи; тогда к нему нужны точка входа CH-02, маршрут PG-02 и меню Telegram.
3. **Граница модулей.**
   - В чужой модуль ведут только на `start` его сторис: переход действия (UI-03 вместе с UI-35), цель-адрес исхода и ссылка уведомления (UI-36).
   - Модуль, в который ведёт один модуль, — вспомогательный с единственным пользователем: нужен второй пользователь, или сторис переезжает к единственному (UI-37). Вход из своей сторис модуль разделом не делает.
   - Связи из меню (корневой сторис набора) не в счёт: модуль, открытый только из меню, — раздел.
4. **Код.**
   - Код экрана — `FE/<m>/logic/<story>/<экран>.scode.ts` (путь зеркалит описание), уведомления — `.ncode.ts`; загрузчик — в `FE/<m>/logic/<m>-codes.ts`, вход оболочки — `FE/<m>/logic/index.ts`.
   - Подмена для тестов — `<M>CodeOverrides` в `<m>-codes.types.ts`; новый модуль — ещё в пересечении `ExampleCodeOverrides` (`R/example-codes.types.ts`).
5. **Представления.**
   - `chat`: `FE/<m>/chat/<story>/<экран>.view.ts` и запись в `FE/<m>/chat/<m>-chat.views.ts`.
   - `web`: `FE/<m>/web/<story>/<экран>.view.ts` и запись в `FE/<m>/web/<m>-web.views.ts`.
   - Telegram — только перекрытие (`FE/<m>/telegram/`), иначе показывает база `chat`.
   - Текстовые страницы — `packages/web-ui/testing/text-views/`: `<экран>.view.ts` рядом с `<m>-pages.views.ts` (место — долг DEBT-UI-42).
   - Вход канала модуля для оболочки — `index.ts`; кирпич для соседних модулей — `public.ts` (образец — `FE/users/chat/public.ts`); кирпич без хозяина — `FE/<канал>-kit/`.
6. **Новый модуль — пять сборок.** Реестр модуля добавляется в каждую:
   - `R/example-codes.ts`;
   - `R/dialog/example-dialog-views.ts`;
   - `R/tg-bot/example-telegram-views.ts`;
   - `R/web/example-web-views.ts`;
   - `packages/web-ui/testing/text-views/example-pages.views.ts`.

   Каждая сборка отбирает реестры фильтром `ModuleRegistries.required(app)` по месту: модуль вне приложения в сборку не попадает (UI-06).
7. **Приложения UI.** Сторис — в `stories` нужных `R/*/*.ui-app.ts`. Сторис, в которую ведёт включённая, но в приложение не вошедшая, отрезана (`omits`): ядро её действие не показывает.
8. **Примеры.** Примеры (`examples`) меряет CH-01 автоматически (`ExampleLimits` в `R/dialog/example-dialog-views.test.ts`); снимок — тестом в `R/<r>/example-*-views.test.ts`, если вид важен.
9. **Проверка — `bun run check`.**
   - `arch:check` проекта — `R/*/example-*.arch.test.ts` (правила графа и слоёв фронта);
   - `NM-01` — `checks/repo-file-names.test.ts`;
   - UI-06 — конструкторы сборок.

   Тесты состава считают свойства набора, а не узлы: упавший тест с числом узлов — дефект теста, а не повод вписать новое число.
