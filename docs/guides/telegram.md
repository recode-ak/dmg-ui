# Telegram — гайд

**Назначение:** как подключить Telegram к приложению UI проекта пакетом `dmg-ui/tg-bot`: что собрать, что подаёт проект, как работают апдейты, тексты, меню и сообщество, чем отвечает Bot API, что проверено на живом Telegram, а что нет. Общая часть мессенджеров (беседа, лимиты, уведомления, сообщество) — [messenger-package.md](./messenger-package.md); общий контракт канала — [channel-package.md](./channel-package.md). Решения и причины — `D-UI-61…68` ([decisions.md](../decisions.md)); здесь они не пересказываются. Сообщество и возможности — [telegram-community.md](./telegram-community.md); отказы, тесты и непроверенное — [telegram-checks.md](./telegram-checks.md).

---

## 1. Когда применять, границы

- Нужен бот Telegram для приложения UI: личный чат с экранами и уведомлениями, меню команд, при необходимости — реакция на события группы (D-UI-61, D-UI-62, D-UI-64, D-UI-65).
- **Диалог — только личный чат.** Группа, канал, `edited_message` беседой не становятся (D-UI-62); группа — отдельный путь, сообщество ([раздел 6](./telegram-community.md#6-сообщество)).
- **Библиотеку и сеть даёт проект.** Пакет не импортирует библиотеку Telegram и не ходит в сеть: он принимает апдейты как есть и вызывает порт `BotApi` (D-UI-61).
- Подлинность апдейта — дело проекта (раздел 3).
- Что нужно человеку на Telegram, но пакет не делает: вложение как вход экрана (сигнал `attachment` приём апдейтов строит, но экран получить вложение во вход не может — правка ядра), «богатые» сообщения, опросы, Mini Apps ([раздел 8](./telegram-community.md#8-что-ещё-из-bot-api-104)).

## 2. Сборка

Порт `BotApi` — восемь методов ([bot-api.types.ts](../../packages/tg-bot/src/bot-api/bot-api.types.ts)): `sendMessage`, `editMessageText`, `editMessageReplyMarkup`, `answerCallbackQuery`, `setMyCommands`, `banChatMember`, `unbanChatMember`, `approveChatJoinRequest`. Параметры — JSON Bot API как есть (`snake_case`); результат — `BotApiResult`: `{ ok: true, result }` или отказ `{ ok: false, error_code, description }`. Отказ — значение, не бросок; бросок порта пакет считает сбоем транспорта. Адаптер порта проекта — несколько строк: отказ библиотеки перевести в значение.

Узлы сборки, все из `dmg-ui/tg-bot`:

| Класс | Роль |
|---|---|
| `TelegramMessenger` | исполняет `MessengerPort` поверх `BotApi`; спека `{ api, logger, now? }`; `messenger.community` — порт сообщества на том же `api` |
| `TelegramUpdates` | `receive(update: unknown)`: апдейт Bot API → сигнал беседы или сообщества; не бросает |
| `TelegramMenu` | `publish()` — один `setMyCommands` по точкам `menu` |
| `TelegramGraphProvider` | поставщик графа Telegram: правила `TG-01…06` |

Порядок: один массив точек входа (раздел 5) идёт и в `ChatAppSpec.entryPoints`, и в `TelegramUpdatesSpec.entryPoints`; `Conversations` получает `messenger`, `people`, `peers` (общая часть — [messenger-package.md](./messenger-package.md)); `TelegramUpdates` — `conversations`, `messenger`, `logger`, `entryPoints`, `bot` и, если есть сообщество, `communities`; при старте — `UiNotifier.start()` и `menu.publish()`.

**Образец — [packages/example/src/runners/tg-bot](../../packages/example/src/runners/tg-bot/README.md)**: `ExampleBot` ([example-bot.ts](../../packages/example/src/runners/tg-bot/example-bot.ts)) собирает всё на порте `BotApi`, не зная сети и библиотеки; `GrammyBotApi` и `GrammyPolling` — адаптер порта и опрос на `grammy`, их проект пишет под свою библиотеку (D-UI-68).

## 3. Подача апдейтов и подлинность

Личность держится на подлинности апдейта (D-UI-62): проект подаёт в `receive` только то, что пришло от Telegram.

- **`getUpdates` или вебхук с секретным токеном.** Пример использует только `getUpdates`: порт не открывается, подлинность держат токен и TLS. Вебхук с секретом пакет не проверяет — проверка заголовка на входе проекта.
- **`allowed_updates`.** `TELEGRAM_ALLOWED_UPDATES` — `message`, `callback_query`, `my_chat_member`, `chat_member`, `chat_join_request`; проект подаёт их в `getUpdates` или вебхук. Без `chat_member` апдейты участников группы не придут ([раздел 6](./telegram-community.md#6-сообщество)).
- **`bot` — id бота.** Берётся из `getMe`; безопасное целое больше 0, иначе бросок при сборке. По нему отсеивается эхо бота ([раздел 6](./telegram-community.md#6-сообщество)); `my_chat_member` не про этот id — не сигнал и `error` без id.
- **Один токен — один исполнитель.** `getUpdates` и вебхук не уживаются, подтверждённый `offset` одного исполнителя съедает апдейты другого; библиотечный `Bot.start` снимает вебхук. Тестовый бот — отдельный, не боевой. Второй экземпляр на том же токене получает 409; пример завершается с понятным сообщением (D-UI-68).
- **Часы сервера.** Срок бана при исключении считается от `now` (по умолчанию `Date.now`) — [раздел 6](./telegram-community.md#6-сообщество).
- **Регистрация человека** — до `receive`, порт `people` проекта: данные Telegram (имя) в пакет не идут (D-UI-62).

Токен читает только точка входа проекта (ARC-09), в лог и трассу он не попадает (ERR-07).

## 4. Текст, ссылки, кнопки, лимиты

Подробности — D-UI-61 и D-UI-66; здесь то, что нужно автору проекта.

- **Текст → `entities`.** `parse_mode` не используется: стили (`bold`, `italic`, `strikethrough`, `code`, `pre`, `blockquote`) и ссылки идут сущностями со смещениями в UTF-16. Экранировать строки людей не нужно. Одиночный суррогат заменяется на U+FFFD; пустой текст — заглушка `TELEGRAM_TEXTS.empty` (Bot API требует 1–4096 знаков).
- **Ссылки** — только `http`, `https`, `tg://resolve` и `tg://user`; остальное остаётся текстом без ссылки (`tg://login`, `tg://proxy`, `tg://join` под чужой подписью — фишинг). Ссылка сильнее кода: на одном диапазоне Telegram показывает код без ссылки, поэтому пакет код снимает (проверено на живом клиенте).
- **Кнопки.** По кнопке в строке; `callback_data` — ссылка беседы, 1–64 байта UTF-8. Цвет — `style` из акцента варианта (`ACCENT_STYLES`), момент — сущность `date_time` (`MOMENT_FORMATS`); [раздел 7](./telegram-community.md#7-возможности-telegram).
- **Правка на месте.** `update` — `editMessageText` того же сообщения; «message is not modified» — успех; прочий отказ с причиной `rejected` (любой код, кроме 403, 429 и 5xx) — откат новым сообщением, прежнее уводит беседа. Без вариантов — явная пустая клавиатура.
- **Ответ на каждое нажатие.** Нажатие диалога отвечает беседа, отвергнутое (чужой человек, не личный чат, нет `data`) — приём апдейтов без текста: «часики» у клиента снимаются, подсказок постороннему нет.
- **Лимиты** (`TELEGRAM_CAPABILITIES`): текст 4096 UTF-16, вариантов 100, подпись кнопки 64 UTF-16, ссылка 64, ответ на нажатие 200 UTF-16. Лимиты держит страж общей части — режет, а не отвергает: лишняя кнопка отбрасывается (`error`), текст сверх предела обрезается с «…» (`warn`) — [messenger-package.md](./messenger-package.md). Предпросмотр ссылок выключен у всех сообщений.
- **Собеседник** — каноническое целое больше 0, безопасное для JS; иначе `rejected` без вызова API: неверный ответ `peers` не отправит экран в группу или канал.

## 5. Точки входа и меню

Точка входа — `ChatEntryPointSpec` (`entry`, `via`, `key`), способ — `TELEGRAM_VIA` (D-UI-64):

| `via` | ключ | как человек приходит |
|---|---|---|
| `command` | имя команды `[a-z0-9_]{1,32}` | набирает `/key` |
| `menu` | то же | выбирает команду в меню бота; от набранной апдейт её не отличает |
| `link` | параметр `[A-Za-z0-9_-]{1,64}` | `t.me/<бот>?start=<key>` |

- **Один массив на два читателя:** `ChatAppSpec.entryPoints` (граф) и `TelegramUpdatesSpec.entryPoints` (приём) — расхождения «граф знает точку, приём нет» нет. `command` и `menu` делят пространство ключей, `link` — своё.
- **`cancel`, `back` и `help`** — команды беседы, занимают имя раньше таблицы (TG-04); `/help` — сигнал `help`, ответ — справка живого экрана отдельным сообщением без кнопок (D-UI-107). В меню команд (`setMyCommands`) пакет их не публикует: при нужде проект зовёт `setMyCommands` сам. Команды нет в таблице — «Такого входа нет.». Имя команды приводится к нижнему регистру. Параметр `/start <параметр>` выбирает вход точки `link` и в сигнал не идёт.
- **Меню.** `TelegramMenu.publish()` — один `setMyCommands` (область `all_private_chats`, описание — название входа); точек `menu` нет — вызова нет, список владельца не затирается. Вызывает проект при старте: пакет сам не публикует. Отказ — недоставка и `warn`, бросок порта — `unavailable`; `publish` не бросает.
- **Правила графа.** TG-01 (способ известен), TG-02 (формат ключа), TG-03 (ключ ведёт на один вход; узлы называются в порядке `id`, не таблицы), TG-04 (не `cancel`/`back`/`help`), TG-05 (есть точка `start`: кнопка «Запустить» в пустом чате шлёт `/start`), TG-06 (до 100 команд, описание 1–256 знаков UTF-16). Полный текст — [rules.md](../reference/rules.md); `TelegramGraphProvider` — поставщик правил, своих узлов не вносит.

## 12. Чеклист проекта

- Пакет импортируется только по входам `dmg-ui/tg-bot` и `dmg-ui/tg-bot/testing`; адаптер вызывает операции через приложение (ARC-08).
- Токен и окружение читает одна точка входа проекта (ARC-09).
- ERR-07 — в логе нет токена, id людей, текстов; порт `BotApi` проекта не пишет в журнал тела вызовов.
- Порт `BotApi` проекта — все восемь методов; отказ библиотеки — значение `{ ok: false, ... }`, не бросок.
- Подача апдейтов: только от Telegram (`getUpdates` или вебхук с секретом); `allowed_updates` = `TELEGRAM_ALLOWED_UPDATES`; один исполнитель на токен.
- `bot` — из `getMe`; `people` — регистрация человека до `receive`; `peers` отдаёт личный чат.
- Один массив точек входа в `ChatAppSpec` и `TelegramUpdatesSpec`; есть точка `start` (TG-05); `menu.publish()` при старте.
- Сообщество, если нужно: бот — администратор; `chat_member` в `allowed_updates`; часы сервера синхронны.
- Тесты на `MemoryBotApi` и `TestUpdates`; пример и пробу запустить на тестовом боте, не боевом; пункты [раздела 11](./telegram-checks.md#11-что-не-проверено-на-живом-telegram) пройти на домене проекта.
- Принятые долги: DEBT-UI-26 (429), 27 (миграция группы), 28 (отклонить заявку), 29 (превью).
