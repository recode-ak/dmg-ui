# Telegram — гайд

**Назначение:** как подключить Telegram к приложению UI проекта пакетом `dmg-ui/tg-bot`: что собрать, что подаёт проект, как работают апдейты, тексты, меню и сообщество, чем отвечает Bot API, что проверено на живом Telegram, а что нет. Общая часть мессенджеров (беседа, лимиты, уведомления, сообщество) — [messenger-package.md](./messenger-package.md); общий контракт канала — [channel-package.md](./channel-package.md). Решения и причины — `D-UI-61…68` ([decisions.md](../decisions.md)); здесь они не пересказываются.

---

## 1. Когда применять, границы

- Нужен бот Telegram для приложения UI: личный чат с экранами и уведомлениями, меню команд, при необходимости — реакция на события группы (D-UI-61, D-UI-62, D-UI-64, D-UI-65).
- **Диалог — только личный чат.** Группа, канал, `edited_message` беседой не становятся (D-UI-62); группа — отдельный путь, сообщество (раздел 6).
- **Библиотеку и сеть даёт проект.** Пакет не импортирует библиотеку Telegram и не ходит в сеть: он принимает апдейты как есть и вызывает порт `BotApi` (D-UI-61).
- Подлинность апдейта — дело проекта (раздел 3).
- Что нужно человеку на Telegram, но пакет не делает: вложение как вход экрана (сигнал `attachment` приём апдейтов строит, но экран получить вложение во вход не может — правка ядра), «богатые» сообщения, опросы, Mini Apps (раздел 8).

## 2. Сборка

Порт `BotApi` — восемь методов ([bot-api.types.ts](../../packages/tg-bot/src/bot-api/bot-api.types.ts)): `sendMessage`, `editMessageText`, `editMessageReplyMarkup`, `answerCallbackQuery`, `setMyCommands`, `banChatMember`, `unbanChatMember`, `approveChatJoinRequest`. Параметры — JSON Bot API как есть (`snake_case`); результат — `BotApiResult`: `{ ok: true, result }` или отказ `{ ok: false, error_code, description }`. Отказ — значение, не бросок; бросок порта пакет считает сбоем транспорта. Адаптер порта проекта — несколько строк: отказ библиотеки перевести в значение.

Узлы сборки, все из `dmg-ui/tg-bot`:

| Класс | Роль |
|---|---|
| `TelegramMessenger` | исполняет `MessengerPort` поверх `BotApi`; спека `{ api, logger, now? }`; `messenger.community` — порт сообщества на том же `api` |
| `TelegramUpdates` | `receive(update: unknown)`: апдейт Bot API → сигнал беседы или сообщества; не бросает |
| `TelegramMenu` | `publish()` — один `setMyCommands` по точкам `menu` |
| `TelegramGraphProvider` | поставщик графа Telegram: правила `TG-01…06` |

Порядок: один массив точек входа (раздел 5) идёт и в `ChatAppSpec.entryPoints`, и в `TelegramUpdatesSpec.entryPoints`; `Conversations` получает `messenger`, `people`, `peers` (общая часть — [messenger-package.md](./messenger-package.md)); `TelegramUpdates` — `conversations`, `messenger`, `logger`, `entryPoints`, `bot` и, если есть сообщество, `communities`; при старте — `UiNotifier.start()` и `menu.publish()`.

**Образец — [examples/tg-bot](../../examples/tg-bot/README.md)**: `ExampleBot` ([example-bot.ts](../../examples/tg-bot/src/example-bot.ts)) собирает всё на порте `BotApi`, не зная сети и библиотеки; `GrammyBotApi` и `GrammyPolling` — адаптер порта и опрос на `grammy`, их проект пишет под свою библиотеку (D-UI-68).

## 3. Подача апдейтов и подлинность

Личность держится на подлинности апдейта (D-UI-62): проект подаёт в `receive` только то, что пришло от Telegram.

- **`getUpdates` или вебхук с секретным токеном.** Пример использует только `getUpdates`: порт не открывается, подлинность держат токен и TLS. Вебхук с секретом пакет не проверяет — проверка заголовка на входе проекта.
- **`allowed_updates`.** `TELEGRAM_ALLOWED_UPDATES` — `message`, `callback_query`, `my_chat_member`, `chat_member`, `chat_join_request`; проект подаёт их в `getUpdates` или вебхук. Без `chat_member` апдейты участников группы не придут (раздел 6).
- **`bot` — id бота.** Берётся из `getMe`; безопасное целое больше 0, иначе бросок при сборке. По нему отсеивается эхо бота (раздел 6); `my_chat_member` не про этот id — не сигнал и `error` без id.
- **Один токен — один исполнитель.** `getUpdates` и вебхук не уживаются, подтверждённый `offset` одного исполнителя съедает апдейты другого; библиотечный `Bot.start` снимает вебхук. Тестовый бот — отдельный, не боевой. Второй экземпляр на том же токене получает 409; пример завершается с понятным сообщением (D-UI-68).
- **Часы сервера.** Срок бана при исключении считается от `now` (по умолчанию `Date.now`) — раздел 6.
- **Регистрация человека** — до `receive`, порт `people` проекта: данные Telegram (имя) в пакет не идут (D-UI-62).

Токен читает только точка входа проекта (ARC-09), в лог и трассу он не попадает (ERR-07).

## 4. Текст, ссылки, кнопки, лимиты

Подробности — D-UI-61 и D-UI-66; здесь то, что нужно автору проекта.

- **Текст → `entities`.** `parse_mode` не используется: стили (`bold`, `italic`, `strikethrough`, `code`, `pre`, `blockquote`) и ссылки идут сущностями со смещениями в UTF-16. Экранировать строки людей не нужно. Одиночный суррогат заменяется на U+FFFD; пустой текст — заглушка `TELEGRAM_TEXTS.empty` (Bot API требует 1–4096 знаков).
- **Ссылки** — только `http`, `https`, `tg://resolve` и `tg://user`; остальное остаётся текстом без ссылки (`tg://login`, `tg://proxy`, `tg://join` под чужой подписью — фишинг). Ссылка сильнее кода: на одном диапазоне Telegram показывает код без ссылки, поэтому пакет код снимает (проверено на живом клиенте).
- **Кнопки.** По кнопке в строке; `callback_data` — ссылка беседы, 1–64 байта UTF-8. Цвет — `style` из акцента варианта (`ACCENT_STYLES`), момент — сущность `date_time` (`MOMENT_FORMATS`); раздел 7.
- **Правка на месте.** `update` — `editMessageText` того же сообщения; «message is not modified» — успех; прочий отказ с причиной `rejected` (любой код, кроме 403, 429 и 5xx) — откат новым сообщением, прежнее уводит беседа. Без вариантов — явная пустая клавиатура.
- **Ответ на каждое нажатие.** Нажатие диалога отвечает беседа, отвергнутое (чужой человек, не личный чат, нет `data`) — приём апдейтов без текста: «часики» у клиента снимаются, подсказок постороннему нет.
- **Лимиты** (`TELEGRAM_CAPABILITIES`): текст 4096 UTF-16, вариантов 100, подпись кнопки 64 UTF-16, ссылка 64, ответ на нажатие 200 UTF-16. Лимиты держит страж общей части — режет, а не отвергает: лишняя кнопка отбрасывается (`error`), текст сверх предела обрезается с «…» (`warn`) — [messenger-package.md](./messenger-package.md). Предпросмотр ссылок выключен у всех сообщений.
- **Собеседник** — каноническое целое больше 0, безопасное для JS; иначе `rejected` без вызова API: неверный ответ `peers` не отправит экран в группу или канал.

## 5. Точки входа и меню

Точка входа — `ChatEntryPointSpec` (`entry`, `via`, `key`), способ — `TELEGRAM_VIA` (D-UI-64):

| `via` | ключ | как человек приходит |
|---|---|---|
| `command` | имя команды `[a-z0-9_]{1,32}` | набирает `/key` |
| `menu` | то же | выбирает команду в меню бота; от набранной апдейт её не отличает |
| `link` | параметр `[A-Za-z0-9_-]{1,64}` | `t.me/<бот>?start=<key>` |

- **Один массив на два читателя:** `ChatAppSpec.entryPoints` (граф) и `TelegramUpdatesSpec.entryPoints` (приём) — расхождения «граф знает точку, приём нет» нет. `command` и `menu` делят пространство ключей, `link` — своё.
- **`cancel`, `back` и `help`** — команды беседы, занимают имя раньше таблицы (TG-04); `/help` — сигнал `help`, ответ — справка живого экрана отдельным сообщением без кнопок (D-UI-107). В меню команд (`setMyCommands`) пакет их не публикует: при нужде проект зовёт `setMyCommands` сам. Команды нет в таблице — «Такого входа нет.». Имя команды приводится к нижнему регистру. Параметр `/start <параметр>` выбирает вход точки `link` и в сигнал не идёт.
- **Меню.** `TelegramMenu.publish()` — один `setMyCommands` (область `all_private_chats`, описание — название входа); точек `menu` нет — вызова нет, список владельца не затирается. Вызывает проект при старте: пакет сам не публикует. Отказ — недоставка и `warn`, бросок порта — `unavailable`; `publish` не бросает.
- **Правила графа.** TG-01 (способ известен), TG-02 (формат ключа), TG-03 (ключ ведёт на один вход; узлы называются в порядке `id`, не таблицы), TG-04 (не `cancel`/`back`/`help`), TG-05 (есть точка `start`: кнопка «Запустить» в пустом чате шлёт `/start`), TG-06 (до 100 команд, описание 1–256 знаков UTF-16). Полный текст — [rules.md](../reference/rules.md); `TelegramGraphProvider` — поставщик правил, своих узлов не вносит.

## 6. Сообщество

Апдейты группы — сигналы сообщества, не диалога (D-UI-65). Общая часть (манифесты, `Communities`, порт сообщества) — [messenger-package.md](./messenger-package.md); здесь особенности Telegram.

```ts
const communities = new Communities({ app, community, messenger, dispatch, context, people, members, keys, handles });
const telegram = new TelegramUpdates({ conversations, messenger, logger, entryPoints, bot, communities });
```

Образец — [telegram-community-story.test.ts](../../packages/tg-bot/testing/telegram-community-story.test.ts).

- **Бот — администратор группы.** `chat_member` — единственный источник `joined` и `left`; он приходит, только если бот администратор и `chat_member` есть в `allowed_updates`. Без этого событий входа и выхода не будет. `my_chat_member` (бота добавили или убрали) и `chat_join_request` приходят всегда.
- **Эхо бота.** `chat_member` с `from.id` равным `bot` (собственные ban, unban, approve) — ничего и без записи, иначе исключение вызвало бы `left` и петлю. Опора — вывод «`from` — бот при действиях самого бота»; в документации Bot API прямо не сказан (раздел «Что не проверено»).
- **`exclude`** — `banChatMember` с `until_date` = сейчас + `EXCLUDE_BAN_SECONDS` (300 с) и сразу `unbanChatMember` с `only_if_banned: true`: если unban не прошёл, бан снимется сам. Срок считается от `now`: срок бана не выше `MIN_UNIX_SECONDS` (1 600 000 000) — часы неверны, `rejected` без вызова API. Ban отказал — unban не вызывается; ban прошёл, unban отказал — недоставка и `warn`, повтор события исполнит оба вызова заново. В супергруппе ban удаляет сообщения человека; вернуться он может.
- **`approve`** — `approveChatJoinRequest`; нужно право бота «приглашать пользователей». Отклонить заявку нельзя — DEBT-UI-28.
- **`invite`** не объявлена в возможностях (CH-03 запретит такую реакцию); метод порта отказывает `rejected` без вызова.
- **Handle.** Группа — каноническое целое меньше 0, участник — больше 0, безопасные для JS; иначе `rejected` без вызова API.
- **Миграция группы в супергруппу.** Отказ с `migrate_to_chat_id` — `rejected` и `warn` «группа перенесена в супергруппу» без id; перепривязки нет — DEBT-UI-27.
- **429.** Недоставка без повтора по `retry_after` — DEBT-UI-26.
- **Лог без данных** (ERR-07): ни id группы, участника, апдейта.

## 7. Возможности Telegram

Уход экрана, отключённое действие, отключённая кнопка, цвет кнопки, момент времени (D-UI-66, D-UI-67, D-UI-92, D-UI-105). Состав Bot API: `style` — 9.4, `date_time` — 9.5, `disabled` — 10.3.

- **Уход экрана.** `retire` с нажатым вариантом — один `editMessageText`: прежний текст и сущности, затем `\n-----\n` и `Вы выбрали: <подпись>`, клавиатура снята (D-UI-92). Не укладывается в 4096 знаков, нажатого нет или он вне вариантов — `editMessageReplyMarkup` без разметки.
- **Отключённое действие.** Действие, которое сейчас нельзя (вид экрана — `disabled` с причиной), — обычная кнопка с пометкой `🚫` в подписи (`🚫 Создать задачу`): `callback_data` есть, `disabled` и `style` нет. Нажатие — ровно один `answerCallbackQuery` с текстом причины, без `show_alert` (тост); сообщение не правится, UC не вызывается. Предел ответа — 200 знаков UTF-16, длиннее обрезает страж `LimitedMessenger`. Причину беседа берёт из живого вида в момент нажатия: стало доступно — вид заново с «Экран обновился.», стало скрыто — «Действие сейчас недоступно.» (D-UI-105).
- **`disabled`.** Отключённая кнопка (Bot API 10.3) в модели порта есть (`DisabledButton`), но мессенджер её не ставит: ушедший экран отключённой кнопкой не закрывается (D-UI-92); не используется и для отключённого действия — у неё нет `callback_data`, причину сказать нечем (D-UI-105).
- **`style`.** Акцент варианта → цвет кнопки: `primary` → `primary`, `positive` → `success`, `danger` → `danger`; без акцента поля нет.
- **`date_time`.** Момент → сущность на всю длину фрагмента; `date` → `d`, `time` → `t`, `dateTime` → `dt`, `relative` → `r`. Запасной текст остаётся в `text`. Со ссылкой остаётся ссылка, с `code` и `codeBlock` момент снимается; с жирным, курсивом, зачёркнутым — обе сущности.

**Что подтвердила проверка на живом Telegram** (тестовый бот, один аккаунт, 2026-11-18; отключённая кнопка — причина D-UI-92):

| Клиент | Отключённая кнопка |
|---|---|
| веб | серая, не нажимается |
| Desktop 7.4.4 | выглядит обычной, нажатие ничего не делает |
| Desktop 6.7.8 | всё сообщение заменено на «не поддерживается» |

Стили, цвет кнопки и подписи, правка на месте, лимиты 64/65 знаков подписи, 100/101 кнопка, 4096/4097 знаков текста, «message is not modified» как успех — подтверждены. Момент с жирным клиент показывает без жирного; Desktop на Linux не выделяет дату в цитате; со ссылкой остаётся ссылка, с кодом — код.


**Перекрытие представления.** Акцент и момент ставит представление экрана: образец — `exampleTelegramViews` (`dmg-ui/tg-bot/testing`), перекрытие через `ChatViews.over` ([messenger-package.md](./messenger-package.md)). Другие мессенджеры показывают подпись и запасной текст.

**Ограничения `ExampleTelegramPreview`** (DEBT-UI-29): превью показывает экран через `TelegramMessenger` на `MemoryBotApi`, но перехватывает `ViewMessage` на пути сборщика показа и берёт только последнее сообщение. В нём нет шапки заместителя, раскладки «Ещё», стража `MessageFit` и ссылок беседы, у вариантов ссылки `1..n`. Запрос живого бота от превью может отличаться — сверять по трассе (раздел 10).

## 9. Отказы Bot API

Разбор — `BotApiFailure` ([bot-api-failure.ts](../../packages/tg-bot/src/bot-api/bot-api-failure.ts), D-UI-61); недоставка — значение `Delivery`, методы мессенджера не бросают.

| Код | Причина (`UndeliveredReason`) | Что делает пакет |
|---|---|---|
| 403 | `blocked` | собеседник заблокировал бота; недоставка и `warn` |
| 429 | `unavailable` | без повтора по `retry_after` — DEBT-UI-26 |
| 500 и выше | `unavailable` | недоставка, без отката |
| прочие (400 и др.) | `rejected` | дефект показа; `warn` |
| 400 «message is not modified» | успех | правка тем же содержимым; при правке текста и `retire` — `ok` |
| `rejected` при правке текста (кроме «not modified») | откат | новое сообщение, прежнее уводит беседа |
| отказ с `migrate_to_chat_id` | `rejected` | группа стала супергруппой — DEBT-UI-27 |
| бросок порта или ответ не по схеме | `unavailable` | `error` без данных |

В `warn` — мессенджер, операция, метод, `error_code`, описание сервера (до 200 знаков, `TELEGRAM_LIMITS.description`) и имя ошибки; ни id, ни текстов, ни `callback_data`.

## 10. Тестирование и пример

- **`MemoryBotApi`** (`dmg-ui/tg-bot/testing`) — `BotApi` в памяти с журналом вызовов; ведёт себя как Bot API: правка неизвестного сообщения — 400, правка тем же — 400 «message is not modified». `failNext`, `throwNext`, `failOn(метод, отказ)` — отказ или бросок следующего вызова; `holdOn(метод)` держит вызов до `release` — очередь сообщества без таймеров. `chat(chatId)` — сообщения глазами собеседника. Операции группы и `setMyCommands` — запись в журнал и `ok`, модели членства нет (D-UI-63).
- **`TestUpdates`** — построитель апдейтов: `text`, `press`, `groupText`, `joined`, `left`, `botAdded`, `botRemoved`, `joinRequest`.
- **Сцены:** [telegram-story.test.ts](../../packages/tg-bot/testing/telegram-story.test.ts) — диалог, уведомление и меню; [telegram-back-story.test.ts](../../packages/tg-bot/testing/telegram-back-story.test.ts) — «Назад», `/back` и подписи без повторов; [telegram-community-story.test.ts](../../packages/tg-bot/testing/telegram-community-story.test.ts) — сообщество.

## 11. Что не проверено на живом Telegram

Пример не имеет сообщества, а ручная проверка шла с одним аккаунтом. Эти пункты покрыты тестами на подставном порте, но живой Telegram их не подтверждал — проверить при первом подключении группы проекта:

- **Группа.**
  - `from` апдейта равен боту при ban, unban и approve — на этом держится отсев эха; опора — вывод, в документации Bot API он прямо не сказан. Если неверно, исключение вызовет `left` и петлю.
  - Бот — администратор: без него `joined` и `left` не приходят.
  - `ChatMemberRestricted.is_member` у участника с ограничениями.
  - Ban в супергруппе удаляет сообщения человека.
  - Принятие заявки без права бота `can_invite_users` — отказ.
  - Регистр входящих команд.
  - Синхронность часов сервера (срок бана 300 с).
  - Миграция группы в супергруппу (DEBT-UI-27).
- **Поручение между двумя аккаунтами.** Назначенному человеку приходит «Вам назначена задача», исполнителю — «Поручение выполнено»; чужой аккаунт получает тишину и ответ без текста на нажатие. На одном аккаунте проверена только блокировка бота: `warn` 403, без падения, доставка возобновляется после разблокировки.
- **Отключённое действие.** Замечают ли тост `answerCallbackQuery` без `show_alert` и как клиенты показывают `🚫` в подписи, в том числе «🚫 Предыдущая страница» (D-UI-105, D-UI-108; пункты Ж1, Ж2 README примера).
- **Справка и меню команд.** `/help` работает, но в меню не публикуется; ждёт ли его клиент в списке (D-UI-107; пункт Ж5).
- **Не доходит и до учебных экранов.** Вебхук и хранилище бесед на диске (пример — `getUpdates` и память).

## 12. Чеклист проекта

- Пакет импортируется только по входам `dmg-ui/tg-bot` и `dmg-ui/tg-bot/testing`; адаптер вызывает операции через приложение (ARC-08).
- Токен и окружение читает одна точка входа проекта (ARC-09).
- ERR-07 — в логе нет токена, id людей, текстов; порт `BotApi` проекта не пишет в журнал тела вызовов.
- Порт `BotApi` проекта — все восемь методов; отказ библиотеки — значение `{ ok: false, ... }`, не бросок.
- Подача апдейтов: только от Telegram (`getUpdates` или вебхук с секретом); `allowed_updates` = `TELEGRAM_ALLOWED_UPDATES`; один исполнитель на токен.
- `bot` — из `getMe`; `people` — регистрация человека до `receive`; `peers` отдаёт личный чат.
- Один массив точек входа в `ChatAppSpec` и `TelegramUpdatesSpec`; есть точка `start` (TG-05); `menu.publish()` при старте.
- Сообщество, если нужно: бот — администратор; `chat_member` в `allowed_updates`; часы сервера синхронны.
- Тесты на `MemoryBotApi` и `TestUpdates`; пример и пробу запустить на тестовом боте, не боевом; пункты раздела 11 пройти на домене проекта.
- Принятые долги: DEBT-UI-26 (429), 27 (миграция группы), 28 (отклонить заявку), 29 (превью).
