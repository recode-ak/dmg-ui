## 11. Граф и правила `PG-01…PG-07`

Канал — второй поставщик графа ([Пакет канала](./channel-package-view.md#5-представление-показ-и-граф): общие шаги вида Def, видов и правил). Страничные отличия:

- **Один поставщик на все приложения web** — `PageGraphProvider` (`PageGraphSpec.apps`, имя `dmg-ui-pages`); два набора UI в одном графе не поддержаны (DEBT-UI-12). Представлений поставщик не принимает: граф строится из описания и оболочки, полноту представлений держит конструктор реестра модуля `PageViews.of(module, …)` и сборка `AppPageViews.of(app, …)` (UI-06, D-UI-118).
- **Точка входа канала** — `PageRouteDef`, вид Def `pageRoute` (шаблон пути и имя входа приложения): узел под приложением, ребро `opens` к экрану входа. Манифест лежит в `src/url/` ([page-route-def.ts](../../packages/web-ui/src/url/page-route-def.ts)): он нужен и графу, и клиенту.
- **Свои правила — префикс `PG`** (ARC-13): PG-01 — маршрут ведёт на объявленный вход, PG-02 — у входа есть маршрут, PG-03…PG-07 — шаблоны, пересечения и параметры маршрутов и экранов, каждый экран набора выражается URL; повторяют проверки сборки `PageUrls` без броска ([rules.md](../reference/rules.md), [graph/](../../packages/web-ui/src/graph/page-graph-provider.ts), D-UI-77). PG-05…PG-07 не видят `transform` схемы (DEBT-UI-34).
- **Представления на DOM.** Граф о представлениях не знает, поэтому DOM-представления правки графа не требуют. Образец без фреймворка — чистые модели плюс прямое построение DOM ([packages/example/src/runners/web](../../packages/example/src/runners/web/README.md), D-UI-85): модель области вычисляется из `PageViewState` и `PageFormModel` и тестируется без браузера на настоящем `PageClient`; тонкий DOM-слой строит тело области заново на каждое состояние, строки людей кладёт только текстом (`textContent`, `value`), ввод полей хранит отдельно. Решений в DOM пять: ветка «есть `reason`», чтение чекбокса, создание `p.help` и `p.reason` с id из `ControlIds`, ветка «есть `help`» (кнопка «Справка») и ветка `open` (`aria-controls` и блок справки); вид поля, подсказка, границы и причина приходят готовыми из модели (D-UI-106). **Справка области** (D-UI-107): страничного класса справки в `web-ui` нет — у страницы три области и нет общей шапки, а у области всегда есть экран по адресу. Содержание даёт ядро: `new ScreenHelp(app).of(view)` по виду области — `HelpSheet` (подпись, подсказка экрана, действия, доступные двери, причины отключённого). Приложение строит модель сам: `HelpLines.of(лист, open)` из `frontend/web-kit` собирает `RegionModel.help` (разделы и строки — слова листа плюс подписи из своих текстов), `RegionFrame` считает её у готового вида и держит вместе с прежним телом при переходе; у пустой области и отказа справки нет. «Открыто» — решение модели: `RegionFrame.toggleHelp()`, открытая справка остаётся при перерисовке того же экрана (перечитывание, приглушение, новая ревизия) и закрывается при смене экрана. В DOM — только разметка из модели: кнопка «Справка» в шапке области (`data-focus-key="help"`, `aria-expanded`, у открытой `aria-controls` на блок `sheet-<область>` из `ControlIds.sheet`) и блок `section.help` с `p` и `ul>li` через `textContent`; после щелчка область заново считает модель из последнего состояния, а не рисует прежнюю, фокус на кнопке переживает перерисовку. Подсказка двери отдельно не выводится — она есть в справке меню; общая справка (`general()`) странице не нужна. Своя область — `PageRegionPresenter<Target>` с любой целью показа. Образец сборки графа — `ExampleWebArch` (`dmg-ui/example`).

## 15. Как тестировать

- **Провод в памяти** — `PageWire`: строки JSON и журнал сообщений; простой ждёт `PageWire.settled()` без таймеров и без счёта ходов (TST-04), пока не завершится вся работа, включая промисы обработчиков сообщений (D-UI-71).
- **Провод на сокете** — [page-socket-story.test.ts](../../packages/web-ui/testing/page-socket-story.test.ts): сервер на порту `0` на настоящем сокете среды, ожидание — только событиями (подписка на источник области, закрытие на сервере, обрыв, сырые кадры). Что чужое событие экран не перечитал, граница — ответ на свой вызов: кадры одного соединения упорядочены, и сигнал, если бы был отправлен, пришёл бы раньше. Перезапуск сервера — `stop(true)` и новый сервер на том же порту над тем же приложением (прежней сессии нет); вкладка — через `PageReconnector` с `ManualPageClock` и `random: () => 0`: паузу тест сдвигает `clock.advance` на срок из `clock.pending()`, перечитывание ждёт по источнику области. Политику пауз и срока `hello` проверяют подставной сокет и те же часы ([page-reconnector.test.ts](../../packages/web-ui/src/client/page-reconnector.test.ts)), обрыв и `attach` вкладки — подставной конец провода ([page-client.test.ts](../../packages/web-ui/src/client/page-client.test.ts)).
- **Текст страницы** — `PageText` (`dmg-ui/web-ui`): подставная цель показа, текстовое представление на трёх областях, `page()` и `region(name)`. Состояния области — по журналу `client.source(region).subscribe(...)`: подписка сразу отдаёт текущее значение, затем каждое новое. Входящие — так же, по `client.inbox()`; срок отсева — подставными часами `ManualPageClock` (`dmg-ui/web-ui/testing`, `clock.advance(ms)`) без таймеров среды.
- **История** — `MemoryPageHistory`: `back()` и `forward()` ждут клиента без таймеров, `entries()`, `position`, счётчики `pushes` и `replaces` — для сцен «шаг» и «замена»; `reloaded()` — те же записи для новой вкладки и `boot()` (перезагрузка); `fail(error)` — отказ браузера до `fail(undefined)`. Режим `deferred` (`new MemoryPageHistory(url, record, 'deferred')`) описывает браузер: `back()` и `forward()` разрешаются сразу, переход приходит по `release()` (как `popstate`), `pending` — неотпущенные переходы, `leaves` — «Назад» перед первой записью (в браузере — уход со страницы); `push` до `release()` снимается им, как в Chrome. Им проверяют промежуточное состояние и гонки действий человека с переходом; итог после перехода — синхронный режим по умолчанию.
- **Адрес в URL** ([page-urls.test.ts](../../packages/web-ui/src/url/page-urls.test.ts)) — круг «адрес → URL → адрес» на каждом примере каждого экрана набора (`def.examples`) и таблица отказов разбора: строка на причину, `not.toThrow()` в каждой.
- **Показ до ответа** — без таймеров: UC удержан заглушкой конца провода, итог проверяется сразу после вызова жеста (до `await`), откат — по журналу `client.source(region).subscribe(...)` после отпуска ответа; сцены — успех, отказ, устаревшая ревизия, перечитывание, обрыв, переход, «Назад», два действия подряд.
- **Граф** — сцена с `PageGraphProvider` и `ArchReport.of(app)` ([page-graph-provider.rules.test.ts](../../packages/web-ui/src/graph/page-graph-provider.rules.test.ts)); общий порядок — в [Пакете канала](./channel-package.md#11-как-тестировать).
- **Сквозные** — [page-story.test.ts](../../packages/web-ui/testing/page-story.test.ts) (сторис на страничном канале: клиент поверх провода в памяти) и приёмочный [channels-story.test.ts](../../acceptance/channels-story.test.ts) (одна сторис, все каналы).
- **Безопасность** — тесты на недоверенный вход: мусор, строка длиннее предела, чужая пара `(module, uc)`, повтор подписки, чужой или пустой `Origin`, негодный пропуск; строка сервера длиннее предела — с обеих сторон.
- **Браузер** — [`browser/`](../../browser/run.ts): клиент DevTools и сценарии `*.browser.test.ts` на настоящем Chrome без окна, запуск `bun run browser` (в `check` не входит; нужен Chrome: `CHROME_BIN` или `google-chrome` в `PATH`; D-UI-103). [packages/example/src/runners/web](../../packages/example/src/runners/web/README.md): сервер на настоящем сокете, сборка клиента `Bun.build` с проверкой запретных входов по метафайлу ([client-bundle.test.ts](../../packages/example/src/runners/web/server/client-bundle.test.ts)), модели представлений на `PageClient` в памяти и ручной чек-лист для того, что без браузера не проверить (перетаскивание, окно, «Назад» и «Вперёд» в живом браузере, политика содержимого, пульс).

**Когда браузерный тест.** Только если без настоящего браузера не проверить: асинхронный `history.back()` (`popstate` и порядок с загрузкой), фокус и клавиатура, доступность причины отключённого действия в DOM, вид поля (атрибуты `type`, `min`, `max`, `step`, связь с подсказкой). Остальное — обычные тесты выше: они быстрее и не требуют Chrome ([D-UI-103](../decisions.md)). Сценарии «Назад» ([example-web-back.browser.test.ts](../../browser/example-web-back.browser.test.ts)) — «Назад» при открытом окне и после закрытия окна кнопкой; ожидание — `page.back()` (до `popstate`) и `page.waitUntil(условие)`, адрес после `replaceState` сразу не читают. Порядок событий истории, на который опирается режим `deferred`, проверяет калибровка ([history-calibration.browser.test.ts](../../browser/history-calibration.browser.test.ts)): красная после смены Chrome — перекалибровать подставу (D-UI-104).

Клавиатура и доступность ([example-web-disabled.browser.test.ts](../../browser/example-web-disabled.browser.test.ts), [example-web-fields.browser.test.ts](../../browser/example-web-fields.browser.test.ts), D-UI-106): `page.press('Tab' | 'Enter' | 'Space')` нажимает клавишу через `Input.dispatchKeyEvent`; `page.tabTo(селектор, max)` жмёт Tab, пока фокус не окажется на элементе, и бросает с селектором и числом нажатий; `page.accessibility(селектор)` возвращает `{ role, name, description, disabled, focusable }` из дерева доступности (вызовы последовательные: параллельные ломают идентификаторы узлов). «Нажатие ничего не отправило» — без таймеров: до нажатия `WebSocket.prototype.send` оборачивается счётчиком, после `press` (он возвращается, когда обработчики отработали) счётчик читается сразу. Наведение проверить нечем: проверяется атрибут `title`, остальное — чек-лист примера.

Справка области ([example-web-help.browser.test.ts](../../browser/example-web-help.browser.test.ts), D-UI-107): два сценария. Первый — кнопка «Справка» достижима `tabTo`, в дереве доступности `button` с именем «Справка», `aria-expanded="false"`, блока справки нет. Второй — Enter открывает блок (`aria-expanded="true"`, `aria-controls` на `sheet-main`): в тексте подсказка экрана и причина отключённого действия, описаний Def нет; фокус остаётся на кнопке; повторный Enter закрывает блок, фокус на кнопке; в меню (`/menu`) в справке видна подсказка двери «Назначенные мне» из сторис. Ожидание — только `waitFor` и `waitUntil`: состояние справки меняется после обработки щелчка, по счёту ходов его не поймать. Содержание справки, открытие, закрытие при смене экрана и приглушение — обычные тесты моделей (`help-lines.test.ts`, `region-frame.test.ts`).

Соединение DevTools — `CdpConnection` на WebSocket Bun без сжатия (`perMessageDeflate: false`: со сжатием кадры изредка приходили испорченными); испорченное сообщение — отказ ожидающих «DevTools: испорченное сообщение…», а не молчаливое «закрыто» (D-UI-103).

## 16. Чеклист проекта

- Привязка к `Bun.serve` по шести условиям [раздела 4.4](./web-channel-wire.md#44-привязка-к-bunserve): лямбды `open`, `message`, `close`; `data` только из `gate.admit`; `maxPayloadLength`; `closeOnBackpressureLimit` и `backpressureLimit`; пульс `sendPings` и `idleTimeout` 60–120 с; заголовки запроса не в лог. Предел частоты рукопожатий — у прокси.
- Предел кадра считается от публичных `MAX_CLIENT_TEXT` и `MAX_SERVER_TEXT`.
- Страница без годного пропуска не получает скрипт клиента (`PageReconnector.connect()` отказа не возвращает) — «Кто вы?» отдаёт сервер приложения.
- `Referrer-Policy` страницы с формой входа — `same-origin`; политика содержимого, `nosniff`, `no-store`.
- Пропуск — cookie `HttpOnly; SameSite=Strict`, под HTTPS `Secure` и `__Host-`; `origins` — в канонической форме.
- Клиент: первая загрузка — `boot()` с `catch`; ссылки внутри страницы — `route(href)`, `href` из `PageClient.url()`; `pagehide` → `close()` переподключателя; `follow(end, attach)`.
- Каждый экран набора приложения страниц выражается URL (PG-07, иначе сборка `PageUrls` бросает); неразборчивый URL ведёт на вход `start`.
- Ожидаемый итог — только `data` и по схеме данных экрана; ревизия жеста — вида области, а не итога.
- Строки людей — только текстом (`textContent`, `value`); приёмников разметки нет.
- Секретов в состоянии экрана и в параметрах адреса нет: историю браузера читает браузер, «Назад» поднимает прежнее состояние.
- Смена человека — решение проекта: перезагрузка своей вкладки, остальные вкладки оповещены событием браузера ([раздел 12](./web-channel-wire.md#12-личность-и-её-смена)).
- Правила `PG-01…PG-07` зелёные в `arch:check` проекта; граф собран одним поставщиком страниц на все приложения web.
