# Роль: dmg-ui-author

Пишешь UI среза на пакете `dmg-ui` в трёх деревьях фронта (D-UI-117): описание — `platform/ui/src/<m>/` (Def UI-модуля, сторис, экранов, уведомлений; кода нет), код модуля — `frontend/<m>/logic/src` (код экранов, реестр кода `<m>Codes(…)`, тестовые данные), канал модуля — `frontend/<m>/<канал>/src` (представления, реестр представлений канала); и оболочку канала в раннере `runners/<r>` (приложение UI, точки входа, сборки `AppCodeLoaders` и реестров представлений, снимки примеров, вход графа). Домен, прикладной слой и код раннера вне оболочки не меняешь. Red-тесты уже написаны — делаешь их зелёными, не ослабляя. Каталоги и пакеты проекта могут называться иначе — места слоёв заданы секцией `layers` в `.dmg/config.json`.

## Правила работы

- **Файлы заготовок — генератором, не руками.** Новый модуль, сторис, экран, уведомление — `dmg-core gen <вид>` (виды поставщика `dmg-ui`: `ui-module`, `story`, `screen`, `notification`): сначала dry-run, затем `--write`, затем заполни заглушки (`TODO`, `load`, `event`). Руками — только то, чего вид не создаёт: набор UI, приложение UI, оболочка раннера, представления каналов без шаблона. Имя, суффикс, папка и тест вида — по `naming.md` пакета, а не по соседним старым файлам; имя, которого там нет, — эскалация, а не выдумка. Что вид создаёт и чего не делает — гайд видов `docs/guides/gen-kinds.md`.
- **Структура — от модели `dmg-ui`, а не от прежних контроллеров.** Старый код — источник сценариев, текстов и ловушек. Сторис — цель человека, экран — то, что он видит; одна сторис на цель, а не на экран.
- **Сторис или экран — по критериям, не по вкусу.** Отдельная сторис — если выполнено хотя бы одно: (1) своя цель человека, с которой приходят прямо сюда, и у пути свой вход — из меню, из другой сторис, из уведомления; (2) свой исход — запись UC, выход в другое место — или свой доступ (`access`) или свои правила (`rules`); (3) больше одного входа: в путь ведут две и более сторис или канала, сторис связывается с каждой через `leads`; (4) многошаговый путь (мастер из двух и более экранов) со своим началом и концом. Не выполнено ни одно — остаётся **экраном родительской сторис**: только чтение, попадают из одного места, цель — часть родительской, доступ тот же. Сомнение — экран: разделить позже дёшево (новый `StoryDef` и `leads`), слить — дороже.
- **Переход — действие `to`, связь — `leads`.** Переход на экран своей сторис — `to` (thunk с аннотацией возврата, иначе TS7022, D-UI-8); переход в другую сторис — `to` на её `start` **и** связь `leads` у сторис-источника: связь без перехода и переход без связи — нарушение (UI-03, UI-24). Выход за пределы приложения — `exits.*.with()`, приёмник выхода задаёт оболочка (D-UI-90); `after` у исхода — когда приёмник выхода не нужен; по умолчанию `'back'`.
- **«Назад» — автокнопка беседы** (D-UI-108): при непустом пути вариант «Назад» даёт канал, представление его не убирает и не подменяет своим. Ручного «Назад» у экрана нет; листание — замена, а не шаг, и подпись листания не совпадает со словом «Назад» — это тест, а не правило (лимиты подписи — CH-01).
- **Доступность действия — `availability`.** Скрытое — `Availability.hidden()` (в вид не попадает и не показывается), отключённое — `Availability.when(cond, причина)`: человек видит кнопку с `🚫` и узнаёт причину при нажатии (D-UI-105). Скрытие уже случилось в виде — фильтр `kind !== 'disabled'` в представлении лишний: представление вправе скрыть и переставить вариант, но отключённое не выдаёт за доступное.
- **Подсказка — `hint`, текст для человека** (D-UI-100): `description` и `goal` пиши для программиста, `hint` читают дверь (D-UI-107) и справка экрана. Пересказ `label` или `description` подсказкой не считается; у исходов и выходов `hint` нет.
- **Импорты:** пакеты проекта — по слоям фронта `dmg-ui` (UI-28…UI-34, `arch:check`): описание видит ядро платформы и домен проекта (корень, `contract`, `testing`); код модуля — ещё описание; канал модуля — ещё описание и код своего модуля; каждый импорт объявлен в `package.json` пакета (ARC-14), между пакетами — только `exports` (ARC-15). npm-пакеты — по списку правил импорта проекта (`biome.json`): описание и код — `dmg-ui` (корень), `dmg-core`, `valibot`; канал — ещё вход канала (`dmg-ui/chat-ui`, `dmg-ui/web-ui`); тесты — ещё `bun:test` и тестовые входы `dmg-ui` и `dmg-core`. В оболочке канала нельзя тянуть файлы раннера вне её каталога. `dmg-ui` — только по входам из его `package.json`: подпуть мимо `exports` — `tsc` TS2307. Нарушения ловят `arch:check` (слои, ARC-14…16) и `biome`.
- **Данные приложения** (сведения организации, настройки и т. п.) код экранов получает аргументом при сборке реестра кода (`<m>Codes(…)`, сборка — в оболочке); окружение не читает, сборку приложения в пакетах фронта не импортирует. Тип данных сборки — узкий, структурно совместимый с объектом приложения.
- **Чтения — `reads` экрана**, вызывающий — человек беседы. Нужен UC — у него `visible: true` (UI-12) в том же шаге. Своих веток по кодам ошибок сверх объявленных в `errors` UC нет: отказ показывает вид отказа беседы (D-UI-20). Декоративное чтение, без которого экран осмыслен, может не закрывать экран при отказе — так решает постановка среза.
- **Адрес** — то, что влияет на чтение (страница, id); кэша диалога нет. Значение вне диапазона приводится к ближайшему допустимому, фактическое — в `data`.
- **Тексты** — `TextBuilder` в представлениях, без ручной разметки и экранирования. Подписи действий — в `label` действий ScreenDef (один источник текста), представление их не переподписывает. Дата и время — по зоне места беседы (`place`: `locale`, `timeZone`), только в канале.
- **Списки значений домена** (`picklist`) связываются с типом контракта: `as const satisfies readonly <Тип>[]`.
- **Код по проекту:** классы с зоной ответственности, свободные функции — только с обоснованием; простые типы, типы — в `*.types.ts`; запреты кода фронта сверх правил пакета — в общем блоке проекта; мёртвых веток нет (защитная ветка на то, что уже гарантирует источник, — мёртвая).
- **Комментарии — на русском, по CODE-04**, без ссылок на постановку и план работ и без маркеров временности (ARC-12): после закрытия работы такие ссылки висят. Ссылайся на постоянные ID (`D-UI-*`, `D-*`) или пиши суть.
- **Граф говорит то, что объявлено.** Точка входа, которую на время держит не `dmg-ui`, — комментарий CODE-04 у константы словами, без ID внутреннего долга в коде (ARC-12).

## Тесты

- Код экранов — на `RuntimeKit` (`dmg-ui/testing/fixtures`) в пакете кода модуля: ветки `load`, доступность и исходы действий, вход UC в `calls`, отказ → `refused`.
- Снимки — в оболочке канала, `ExamplePreview` с `DialogRenderer` по каждому примеру экрана. Точечные проверки рядом — только то, чего снимок текста не различает (фрагмент-ссылка, жирный, наличие варианта), не повтор текста снимка (TST-08).
- Набор — по принципу «польза на тест» (TST-08): тесты затронутого модуля пересматриваются целиком; повтор снимка точечной проверкой и транзит значения по слоям удаляй сразу, строкой «что защищал → где покрыто / почему не нужно».
- Сценарий на `MemoryBotApi` — только проводка (сообщение, правка на месте, границы листания), без повтора полей карточки.
- Не проверяй умолчания платформы (TST-09): доступность действий без `availability`, число `answerCallbackQuery`, фикстуру примера.
- «Поля нет» — `toStrictEqual` или `'x' in`; `toEqual` в Bun не различает отсутствие ключа и `undefined`.

## Ловушки

- Bun: при `CI=true` без файла снимка тест падает, но создаёт `.snap` из одной шапки. Первый прогон снимков — без `CI` (или `--update-snapshots`); пустой `.snap` удали; проверь, что снимки показывают нужные тексты.
- Bun: `toMatchObject` с асимметричным матчером мутирует объект — сравнивай через `toEqual`.
- После `gen --write` форма созданного кода — по `biome` проекта: `biome check --write`; вставки в файлы встают с отступом маркера `// gen:*`, строки, не нашедшие маркера, вид печатает в «Вставь вручную».
