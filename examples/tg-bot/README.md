# Пример Telegram-бота

Запускаемый пример подключения `dmg-ui/tg-bot` к настоящему Telegram ([D-UI-68](../../docs/decisions.md)): учебное приложение (задачи, поручение другому человеку, уведомление) на порте Bot API, адаптер и опрос на библиотеке `grammy`. Он нужен для ручной проверки по чек-листу ниже: допущения пакета о Bot API (серая кнопка, цвет кнопки, дата в тексте, пределы) тестами на подставном порту не подтвердить.

Сборка узла (`example-bot.ts`) не знает ни сети, ни библиотеки: порт Bot API — параметр. Библиотека `grammy` импортируется только из `grammy-bot-api.ts` (порт), `grammy-polling.ts` (опрос) и их файлов типов; `grammy` — зависимость разработки репо, потребителям пакета она не нужна. Апдейты приходят только длинным опросом `getUpdates`: порт не открывается, публичный адрес и секрет вебхука не нужны. Беседы хранятся в памяти: после перезапуска они забыты.

## Запуск

1. `bun install` в корне репо.
2. Взять **отдельного тестового бота**, не боевого, у BotFather. `Bot.start` библиотеки снимает вебхук бота, а на одном токене может работать один исполнитель: остановите любого другого (старый бот, `pm2`, второй терминал) до запуска. Пример подтверждает полученные апдейты (offset) и поэтому съедает их у другого исполнителя на том же токене, а `allowed_updates`, заданный примером, остаётся на боте и после остановки: поэтому нужен отдельный тестовый бот.
3. Создать `.env` в корне репо из [`.env.example`](.env.example) (`cp examples/tg-bot/.env.example .env`) и заполнить значения. Bun читает `.env` сам; файл в `.gitignore`, токена нет ни в `git status`, ни в `git diff`.
4. `bun run example:tg`. В консоль идут: имя бота, «готов», uuid пользователя B (его вводят в «Назначить») и число команд меню; токена и id людей нет.
5. `bun run example:tg:probe <chat_id>` — проба Bot API (группа Е): бот присылает в чат набор сообщений, каждое начинается со строки «что смотреть». По Enter в консоли проба убирает кнопки сообщения Е7 («ушедший экран»). Проба читает тот же `.env` и требует `EXAMPLE_TG_USERS`. Проба не опрашивает апдейты: нажатия в её сообщениях не обрабатываются. `<chat_id>` — id Telegram человека (для личного чата совпадает с ним), которому надо хоть раз написать боту.

Остановка — `Ctrl+C`: опрос завершается, беседы закрываются. Второй экземпляр на том же токене завершается сообщением о конфликте `getUpdates` (409), первый продолжает работу.

## Переменные окружения

Читает только `main.ts` (и `probe.ts`); остальной код получает значения параметрами.

| Переменная | Что это | По умолчанию |
|---|---|---|
| `EXAMPLE_TG_TOKEN` | токен тестового бота от BotFather | обязательна |
| `EXAMPLE_TG_USERS` | один или два id Telegram через запятую: первый — пользователь A, второй — B; кого нет в списке, бот не слышит | обязательна |
| `EXAMPLE_TG_LOG` | уровень журнала в консоли: `debug`, `info`, `warn`, `error` | `info` |
| `EXAMPLE_TG_TRACE` | путь файла трассы исходящих вызовов (см. ниже) | трассы нет |
| `EXAMPLE_TG_DATA` | каталог данных учебного мира (задачи, лог операций); внутри репо не задавать: данные людей не должны попасть в git | новый временный каталог |

Учебные пользователи: A — `00000000-0000-4000-8000-000000000001`, B — `00000000-0000-4000-8000-000000000002`. Свой id Telegram можно узнать у бота @userinfobot. В консоль примера id людей не попадают, поэтому чужой id оттуда не прочитать.

## Трасса вызовов

С `EXAMPLE_TG_TRACE=examples/tg-bot/.trace/trace.jsonl` пример дописывает в файл по строке JSON на каждый исходящий вызов Bot API: `method`, `params`, `ok` и, при отказе, `error_code`. Токена в вызове нет, но в файле лежат тексты и id людей: каталог `examples/tg-bot/.trace/` в `.gitignore`, файл не коммитить и не прикладывать к обращениям и отчётам. Для пункта Б14 чек-листа — выбрать текст, разметку и кнопки живых запросов и сравнить со снимками превью в `packages/tg-bot/testing/example/__snapshots__/example-telegram-preview.test.ts.snap`:

```sh
jq -c 'select(.method == "sendMessage" or .method == "editMessageText") | {text: .params.text, entities: .params.entities, reply_markup: .params.reply_markup}' examples/tg-bot/.trace/trace.jsonl
```

## Чек-лист ручной проверки

Каждому пункту в колонке «Итог» ставится «пройден» или «не пройден: что видно». Расхождение с живым Telegram — находка: допущение подтверждено — записать в D-UI-67; не подтверждено — правка кода пакета с тестом до выпуска. В колонке «Откуда» — решения пакета ([`docs/decisions.md`](../../docs/decisions.md)) и правила.

Запуск — `bun run example:tg:probe <chat_id>`; пункты идут сообщениями в чат в этом же порядке. Их сообщения показывает настоящий код пакета: сущности, страж лимитов, `retire`.

| Проба | Ожидаемое | Откуда | Итог |
|---|---|---|---|

| Е2. Ссылка поверх строчного кода | Видна ссылка, без вида кода: ссылка сильнее кода (код под ссылкой Telegram показывает без ссылки) | D-UI-61 | |

## Что пример не проверяет

Сообщества в учебном домене нет, поэтому группу и всё, что связано с её участниками, нужно проверять на домене проекта, который подключает пакет:

- бот — администратор группы (иначе `joined` и `left` не придут);
- `from` апдейта равен боту при бане, разбане и принятии заявки (отсев эха);
- `ChatMemberRestricted.is_member` у участника с ограничениями;
- бан в супергруппе удаляет сообщения участника;
- принятие заявки без права бота `can_invite_users` — отказ;
- регистр входящих команд;
- синхронность часов сервера (срок бана 300 с);
- миграция группы в супергруппу.

Учебные экраны и проба до этого тоже не доходят:

- серая кнопка в живой беседе: беседа показывает её, только когда правка сообщения невозможна (отказ Telegram) и нажатый вариант открывает новое сообщение; на обычном ходе экраны правятся на месте и серой кнопки нет — смотреть её надо пробой Е7;
- действие, после которого экран не меняется («message is not modified»): учебные сторис такого не дают, это проверяет проба Е12;
- обрезка пробелов сервером, `quote` вместе с `code` и ссылка поверх `code` в живой беседе: тексты задач — простой текст, из сущностей в беседе только дата; эти случаи — пробы Е2, Е4, Е11;
- 100 кнопок и текст на пределе 4096: учебные списки малы (проба Е9, Е13);
- вебхук и хранилище бесед на диске: пример подаёт апдейты только через `getUpdates` и держит беседы в памяти; это граница примера, а не его пункт.
